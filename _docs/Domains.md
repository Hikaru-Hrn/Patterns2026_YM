# Описание доменных моделей и сущностей проекта

Редакция: **2026-10-03**

В таблице ниже приведено описание всех сущностей доменной модели приложения автоматизации сети ресторанов «Ромашка».

| Наименование сущности | Описание | Связи с другими сущностями |
| :--- | :--- | :--- |
| **abstract_model** | Базовый абстрактный класс для всех моделей. Обеспечивает автоматическую генерацию уникального строкового идентификатора (`unique_code` на базе UUID4) и перегрузку операции сравнения `__eq__`. | Родительский класс для `entity_model` и `settings_model`. |
| **entity_model** | Промежуточный абстрактный класс для именованных сущностей. Инкапсулирует валидируемое свойство `name` (непустая строка длиной до 50 символов). | Наследует `abstract_model`. Базовый класс для всех прикладных справочников. |
| **group_model** (Группа номенклатуры) | Классификатор товарных позиций и сырья (например: «Ингредиенты», «Готовые блюда», «Бакалея»). | Наследует `entity_model`. Включается в `nomenclature_model` (связь 1:N). |
| **range_model** (Единица измерения) | Единица измерения количества (граммы, килограммы, штуки, литры). Содержит коэффициент пересчета (`conversion_factor`) и ссылку на базовую единицу измерения (`base`). | Наследует `entity_model`. Ссылается на саму себя (`range_model`) для иерархии единиц. Включается в `nomenclature_model`. |
| **warehouse_model** (Склад) | Место хранения материальных ценностей (сырья, заготовок, готовой продукции). Содержит адрес помещения (до 255 символов). | Наследует `entity_model`. Используется в складских и производственных операциях `storage_manager`. |
| **organization_model** (Организация) | Карточка юридического лица предприятия. Хранит наименование, ИНН (10 цифр с проверкой контрольной суммы), БИК (9 цифр), расчётный счёт (20 цифр с проверкой КС по БИК), форму собственности (`owner`, до 50 символов). | Наследует `entity_model`. Включается в состав `settings_model`. |
| **nomenclature_model** (Номенклатура) | Карточка товара, сырьевого ингредиента или готового кулинарного изделия. Содержит краткое имя (до 50 символов), полное наименование (до 255 символов), ссылку на группу и единицу измерения. | Наследует `entity_model`. Агрегирует `group_model` и `range_model`. Хранится в `storage_manager`. |
| **recipe_row_model** (Строка рецепта) | Строка технологической карты, определяющая конкретную номенклатурную позицию (ингредиент, полуфабрикат или тару), единицу измерения, нормы веса брутто и нетто. | Наследует `abstract_model`. Ссылается на `nomenclature_model` и `range_model`. Входит в состав `receipt_model`. |
| **receipt_model** (Технологическая карта) | Документ рецепта, определяющий состав блюда или полуфабриката, описание технологии и вычисляющий общий вес брутто и нетто. | Наследует `entity_model`. Ссылается на выходную номенклатуру `nomenclature_model`. Агрегирует строки `recipe_row_model`. Хранится в `storage_manager`. |
| **settings_model** (Модель настроек) | Контейнер конфигурационных параметров системы: карточка организации, ФИО руководителя (`boss_name`), ФИО главного бухгалтера (`account_name`), флаг первого старта (`first_launch_flag`), формат отчета по умолчанию (`response_format`). | Наследует `abstract_model`. Содержит `organization_model` и `report_type_enum`. Управляется `settings_manager`. |
| **report_type_enum** | Перечисление поддерживаемых форматов отчетов: `TXT`, `CSV`, `MARKDOWN`, `XML`, `HTML`. | Используется в `settings_model`, `report_factory` и REST API. |
| **report_result_dto** | DTO-модель для передачи результата формирования отчета. Содержит структурированный текст (`text`) или бинарные данные (`binary`) для скачивания. | Наследует `entity_model`. Формируется классами отчетов. |
| **abstract_report** | Базовый абстрактный класс для алгоритмов формирования отчетов. Задает контракт метода `build(source) -> report_result_dto`. | Родительский класс для `text_report`, `csv_report`, `markdown_report`, `xml_report`, `html_report`. |
| **report_factory** | Фабрика для инстанцирования нужного класса отчета по запрошенному формату или по умолчанию из настроек (`create_default`). | Наследует `abstract_report_factory`. Инкапсулирует `settings_model`. |
| **common** | Сервисный класс рефлексии метаданных доменных моделей (`get_fields`, `get_entity_header`, `get_entity_table`). Обеспечивает универсальное извлечение атрибутов моделей для отчетов без привязки к конкретным типам. | Используется всеми классами отчетов для обхода любых моделей. |
| **entity_description_header_dto** | DTO-модель описания одного скалярного поля сущности (`field`, `value`). | Формируется методом `common.get_entity_header()`. |
| **entity_description_table_dto** | DTO-модель строки табличной части агрегата (`columns`, `values`). | Формируется методом `common.get_entity_table()`. |
| **abstract_manager** | Базовый абстрактный класс для менеджеров обработки данных. Задает контракт методов `load()`, `convert()` и свойство `is_loaded`. | Родительский класс для `settings_manager` и `storage_manager`. |
| **settings_manager** | Менеджер загрузки и парсинга конфигурации из файла JSON (`settings.json`). Реализован по шаблону Singleton. | Наследует `abstract_manager`. Создает и хранит экземпляр `settings_model`. |
| **storage_manager** | Хранилище доменных справочников в оперативной памяти (Singleton). Обеспечивает уникальность объектов складов, единиц измерения, групп, номенклатуры и рецептов, а также первичное наполнение при первом старте. | Наследует `abstract_manager`. Использует `settings_manager` для чтения настроек. Хранит коллекции `warehouse_model`, `range_model`, `group_model`, `nomenclature_model`, `receipt_model`. |
